# 语法表达与错误语义

本文档说明本仓库接受的语法表达方式、冲突检测规则与解析错误语义。

## 1. 词法规则

`grammar.LexerRule` 字段：

| 字段 | 含义 |
|---|---|
| `Name` | 词法单元名，被产生式中的 `Terminal(name)` 引用 |
| `Pattern` | Go `regexp` 语法的正则表达式 |
| `Priority` | 优先级，数值越大越优先 |
| `Ignore` | 为 true 时匹配结果被词法层丢弃（如空白、注释） |

匹配语义（在同一输入位置）：

1. **最长匹配优先**：匹配文本更长的规则胜出；
2. **等长比优先级**：长度相同取 `Priority` 数值大者；
3. **等长且同优先级 = 冲突**：若两条规则模式与优先级完全相同，
   在**生成期**即被拒绝（`duplicate/identical pattern`）；
   运行期若正则在等长等优先级下产生平局，词法分析以错误失败，绝不二选一。
4. **忽略规则**不进入 token 流，因此**不能**被产生式引用（生成期报错）。

生成期被拒绝的声明问题：空规则名、重名、空模式、非法正则。

## 2. 产生式与组合子

- `Rule`：`Name := Alt1 | Alt2 | ...`，至少一个候选分支；
- `Alternative`：`Term` 的有序序列；空序列即空产生式（epsilon）。

构造器：

| 构造器 | 语义 |
|---|---|
| `Terminal(name)` | 词法单元 |
| `NonTerminal(name)` | 规则引用 |
| `Optional(seq)` | 0 或 1 次 |
| `ZeroOrMore(seq)` | 0 次或多次（贪婪；空匹配保护，不死循环） |
| `OneOrMore(seq)` | 1 次或多次 |
| `Group(seq)` | 括号分组 |
| `Seq(terms...)` | 顺序分支 |
| `Epsilon()` | 空分支 |

运行时为分支生成对应的结构节点；组合子生成合成节点
（符号为 `?`/`*`/`+`/`()`），其 `Children` 为实际匹配内容。

## 3. 左递归

直接左递归（`E = E "+" N | N`）与间接左递归
（`A = B "x" | "a"; B = A "y" | "b"`）均被支持。

运行时使用 Warth et al.（2008）的种子生长（seed-growing）packrat：

- 第一次遇到递归返回失败种子，随后以非递归分支为种子迭代生长；
- 每轮必须严格消费更多输入，否则停止；
- 互递归通过 head/involved/eval-set 传播，
  最终解析树为左结合形态。

## 4. 冲突检测（存在歧义必须拒绝）

生成期对每条规则做可判定检查；候选分支首先按
**是否处于左递归位置**划分为种子分支与递归臂：

- 递归臂：分支左缘（经可空前缀）可到达本规则，
  递归点 = 最左的递归符号。
- 种子分支：其余候选。

检查规则：

1. **种子/种子 FIRST 冲突**：两个种子分支可以相同词法单元起始
   （FIRST/FIRST）→ 拒绝。需要把公共前缀提出（因子化）。
2. **可空种子**：至多一个可空分支；若存在，其它分支的 FIRST
   不得与该规则的 FOLLOW 集相交（FIRST/FOLLOW）。
3. **序列内部歧义**：序列中可空元素（可选/重复）的 FIRST
   不得与其后续符号的 FIRST 相交。
4. **递归臂/臂冲突**：两个递归臂递归点之后的尾部 FIRST 相交 → 拒绝。
5. **尾部右缘回到本规则**：如 `E = E "+" E | "n"` 是经典的
   关联歧义（`n+n+n` 有两种括号化），本服务**拒绝**它，
   要求引入优先级分层：

   ```
   expr = expr "+" term | term
   term = term "*" atom | atom
   atom = NUM | "(" expr ")"
   ```

   注意：`atom` 中括号包裹的 `expr` 不属于右缘回归（其右侧有 `")"`），
   因此该表达式文法可正常通过。

6. **非空前缀后的左递归**：递归符号左侧的前缀若能推出非空串
   （如 `s = opt s "x" | "x"` 且 `opt` 可匹配 `"y"`），
   贪婪运行期无法确定解析，生成期拒绝；
   前缀只能取空（如 `opt` 仅有 epsilon 分支）时允许。

> 关于判定的保守性：一般上下文无关文法的歧义性不可判定，
> 本服务采用可判定的保守检查（LL(1) 家族 + 左递归特化），
> 宁可拒绝无法证明确定性的文法，也不静默接受潜在歧义。
> 被拒绝时可按诊断提示因子化或引入优先级分层。

7. **结构性拒绝**：重名规则、未定义引用（规则或词法单元）、
   引用被忽略词法规则、无候选分支、不可产生规则
   （永远推不出终结符串，如无基分支的左递归）。
8. 不可达规则给出**警告**（不阻止生成）。

检查不通过时 `Generate` 返回 `nil` artifact 与非空 `ConflictReport`，
诊断含级别、关联规则与原因。运行时不做静默的歧义选择：
无静态歧义时 packrat 的有序求值结果唯一。

## 5. 解析结果

`parser.Result`：

- `Root *Node`：结构化语法树（快速失败时为 nil）；
- `Errors []*Error`：错误集合；
- `Consumed int`：成功消费的字节数；
- `OK()`：无错误且 Root 非空。

`parser.Error` 字段：

- `Offset`：字节偏移；
- `Line` / `Column`：1 起始的行号与列号（列按 **rune** 计算，
  多字节字符不影响后续列）；
- `Expected` / `Found` / `Msg`：期望集合（排序去重）、实际符号、
  可读描述；
- `FromLexer`：区分词法错误与语法错误。

期望集合按 PEG 最远失败点（farthest failure）计算，
仅在出错路径上构建行列索引——**无错误输入不付出额外代价**。

## 6. 恢复策略

`parser.Config.Recovery`：

| 模式 | 行为 |
|---|---|
| `RecoveryFailFast`（默认） | 遇到第一个错误立即停止，不返回部分树 |
| `RecoverySkipToken` | 从失败位置丢弃一个 token，重试起始规则，逐段收集 |
| `RecoverySync` | 跳过 token 直到命中 `SyncTokens` 中的词法单元（或末尾）再重试 |

语义保证：

- **不漏报**：每个无法解析的输入区域都产生一条错误；
- **不重复**：同一偏移同一内容的错误只报告一次
  （以 `偏移|内容` 去重）；词法错误与语法错误位于同一偏移时，
  只保留词法错误（根因）；
- **保证前进**：每次恢复至少跳过一个 token，不会死循环；
- `MaxErrors > 0` 时限制收集错误数。

恢复成功后返回合成根节点，`Children` 为各段解析出的完整子树。

## 7. 并发与复用

- `generator.Generator` 无状态，可并发调用、长期复用；
- `Artifact` 构造后不可变，其内部解析器与词法器只读；
- `Parse` 的备忘录、错误收集器、token 流、行列索引均为
  每次调用独立的 session，不写任何共享状态（经 `-race` 验证）；
- 单次解析的备忘录在恢复分段之间复用（packrat 结果上下文无关）。

## 8. 增量校验

`incremental.Checker`：

1. 以规则的规范化哈希找出内容变化的规则集 C（新增/删除/修改）；
2. 受影响闭包 = C ∪ C 的传递依赖者；更深层的 FOLLOW 传播
   由事实引擎在检测到事实**实际偏差**时动态激活，不做静态过度扩展；
3. 结构索引（依赖图、FOLLOW 出现位置）跨校验增量打补丁；
4. 未受影响规则的事实只读复用、诊断按规则名结转；
5. 词法规则或起始规则变化时回退全量校验。

校验通过后产物即时再生成；语法指纹按分段哈希增量维护。
`LastAffected()` 返回实际重算的规则集，便于观测增量范围。

## 9. 版本兼容性

- `version.FingerprintOf(g)`：分段哈希（名称/起始规则、每条词法规则、
  每条产生式）XOR 组合，与声明顺序无关；
- `version.Check(old, new)` / `Artifact.CheckCompatibility(new)`：
  返回全部差异（词法规则增删改、产生式增删改、起始规则、语法名），
  每条差异带明确原因；不兼容时 `Compatibility.Compatible == false`。
